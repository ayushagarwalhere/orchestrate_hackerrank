# Request interpretation and reusable evidence ledger

Request authorization and evidence coverage are separate decisions. Reliable rules identify deletion, access, correction, export, marketing opt-out, restoration and questions; conflicting, conditional or unsupported language remains UNSURE. Permitting legally required retention qualifies treatment and does not negate an otherwise clear deletion request. An ambiguous request may use the versioned classification-only prompt, with a closed JSON schema, literal supporting spans and explicit unknowns. A missing, invalid or failed model answer cannot become NOT_APPLICABLE. Unresolved authorization blocks publication.

The ledger is built once, before requests are investigated. Each manifest file receives an extraction record with source identity/hash, format, status, duration, observation count and any fixed failure code. Missing extraction, parser failures, visual-review requirements, unresolved references and system coverage remain separate from observations and findings. Observations retain both clocks, system/resource/category/state, identifying-field presence/value and a precise table/row, JSON pointer, line, PDF page or screenshot-record location. Lookup selectors remain ownership keys rather than stored identifying fields.

SQL, JSON, handovers, logs, PDF text and validated screenshot facts feed the same typed model. Empty parser output is not absence. Only an explicit scoped authoritative snapshot or an actual negative lookup can support absence; a raw empty file cannot. Unknown field/state and reference information is retained. A file with insufficient PDF text requires rendered-page inspection or a trusted visual extractor; missing screenshot facts and partial visual extraction block publication. Rendering and inspection do not invent resource IDs.

The actual AuditAgent receives this index once and passes the same object to investigation. Coverage failures block output before findings are compiled. Source-local errors are collected so the ledger can describe all files, rather than dropping everything after the first bad file. Aggregate traces contain counts/fixed failure types, not customer text, identifying fields or credentials. Detailed ledger contents remain local source data.

Run `python code/main.py --no-llm --trace diagnostics/trace.json --ledger diagnostics/ledger.json` to export `evidence-ledger/v1`. The detailed ledger includes every observation and per-file extraction outcome, both successful and failed. It is written atomically and cannot replace the dataset, CSV or aggregate trace. An index failure still records its ledger when requested. Weak PDF pages are rendered for review; a supplied visual reader must explicitly return complete text. Blank screenshot facts require review rather than proving an empty store.

Unbound visual labels, external order/ticket references and resource references remain explicit candidates. They do not manufacture resource IDs or become findings. Parsed identifying fields preserve source values and distinguish missing, null and unknown. PDF text retains unresolved names/text for review, and visible international phone values retain their country prefix. System coverage lists observed systems/files and declared snapshot scopes; it is not a statement of exhaustive access to every physical store.

This change does not make the inherited workflow timing, case-order tie breaks, naming fallback or retrospective ownership proof reliable. They remain disclosed assumptions. Physical-copy state reduction and general indirect-identification analysis also remain limitations. New classification prompts preserve older cache provenance by using a new version/path; historical v2 screenshot extractions are not relabeled or regenerated. Tests and frozen before/after predictions distinguish structural preservation from intentional correctness changes.
